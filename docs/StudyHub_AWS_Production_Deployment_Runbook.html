4. Issues Encountered & Solutions Applied

⚠️ Issue 1: SSH Port 22 Connection Timed Out
Cause: EC2 was launched in subnet studyhub-private-2b attached to a private route table routed only to a NAT Gateway.
Solution: Associated studyhub-private-2b with studyhub-public-rt (rtb-032c88d4d3472f501), routing directly to the Internet Gateway.
⚠️ Issue 2: SSH Connection Reset & Out Of Memory (OOM) During Builds
Cause: Compiling Next.js 16 across multiple containers simultaneously consumed 100% CPU and exhausted physical RAM.
Solution: Created a 4GB Swap file (/swapfile), added -o ServerAliveInterval=60 to SSH, and built containers sequentially.
⚠️ Issue 3: Next.js Standalone Build in Monorepo
Cause: Next.js does not generate standalone output folders without explicit configuration.
Solution: Configured output: 'standalone' in apps/web/next.config.ts and apps/admin/next.config.ts.
⚠️ Issue 4: Admin Docker Build Missing public/ Directory
Cause: apps/admin lacked a public folder, breaking the Dockerfile COPY step.
Solution: Added RUN mkdir -p apps/admin/public and created apps/admin/public/.gitkeep.
⚠️ Issue 5: Prisma 7 Build-Time Generate Failure
Cause: Prisma 7 requires a DATABASE_URL environment variable even during client generation.
Solution: Passed a dummy build-time variable: DATABASE_URL="postgresql://build:build@localhost:5432/build" npm run db:generate.
⚠️ Issue 6: Node 24 ESM Module Resolution (API & Worker)
Cause: Node 24 ESM requires explicit .js extensions on compiled relative imports and ignores TypeScript path aliases.
Solution: Configured Dockerfile.api and Dockerfile.worker to execute with npx tsx --tsconfig ....
⚠️ Issue 7: Missing package.json in API Runtime Container
Cause: Runtime stage omitted root package.json, causing workspace npm commands to fail with ENOENT.
Solution: Added COPY --from=build /app/package.json /app/package-lock.json ./ to both Dockerfiles.
⚠️ Issue 8: RDS PostgreSQL Port 5432 Connection Timed Out
Cause: The RDS Security Group only allowed incoming traffic from itself, blocking the EC2 server (10.0.87.55).
Solution: Added an Inbound Rule to sg-0ef77fb4a0998ff9a for PostgreSQL port 5432 from 10.0.0.0/16 (VPC CIDR).
